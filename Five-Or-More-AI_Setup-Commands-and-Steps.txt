--------------------------------------------------
15. ACTION / PLAYER MOVE
--------------------------------------------------

Human input flow:

Mouse click on a piece
        ->
Piece selected
        ->
Mouse click on destination tile
        ->
CalculateMovementPathEvent
        ->
A* pathfinding
        ->
Movement
        ->
Move validation
        ->
Line detection / scoring
        ->
Spawn new pieces

The important action concept for RL is:

SOURCE -> DESTINATION

Example:

(x1, y1) -> (x2, y2)

The AI should eventually choose a move in logical coordinates rather than pixel coordinates.

--------------------------------------------------
16. PATHFINDING
--------------------------------------------------

src/event_handlers/calculate_movement_path_event_handler.rs

The game uses:
petgraph::algo::astar

A* calculates a path from the selected piece to the target tile.

Occupied cells are treated as obstacles.

Movement is horizontal/vertical through adjacent cells.

Therefore:
The RL agent does NOT need to learn pathfinding.

The agent can choose:
piece + destination

The existing Rust game can handle:
pathfinding + movement.

--------------------------------------------------
17. MOVEMENT
--------------------------------------------------

src/systems/move_pieces.rs

The piece follows the calculated path.

Once it reaches the final destination:

piece.set_coord(coord)

Then:

ValidateMoveEvent

is sent with:

NextPlannedMove::SpawnPieces

So the move is logically completed before the next game stage.

--------------------------------------------------
18. SCORING / REWARD INFORMATION
--------------------------------------------------

src/event_handlers/validate_move_event_handler.rs

The game checks:
- horizontal
- vertical
- diagonal right-down
- diagonal right-up

A line is cleared when length >= 5.

Current score rules:

5 balls = 10 points
6 balls = 12 points
7 balls = 14 points
8 balls = 16 points
9 balls = 18 points

These are the game's native scoring rules.

IMPORTANT:
Do not automatically assume the game's score is the final RL reward design.
Reward shaping will be a later research/design decision.

--------------------------------------------------
19. NEW PIECE SPAWNING
--------------------------------------------------

After a normal move, the game sends:

SpawnNewPiecesEvent::new(3)

Therefore:
- 3 new pieces normally spawn after a move.
- Random positions are selected.
- Random colors are selected.
- New pieces cannot overlap existing pieces.

If the board has no empty space, game over is triggered.

--------------------------------------------------
22. PROJECT APPROACH DECISION
--------------------------------------------------

We considered:
1. jackinf/lines Rust implementation
2. GNOME Five or More
3. Building a Python-only game environment

Decision:
Continue with jackinf/lines.

Reason:
- Already runs successfully.
- Small and understandable source.
- Game state is accessible internally.
- Action pipeline is understandable.
- Existing A* pathfinding can be reused.
- Existing scoring and spawning can be reused.
- Suitable for a 4-month Master's project.

Caveat:
It is NOT a ready-made RL environment. We will need to add a small RL interface.
